# 相近语法内容质量标准

适用于 `JapaneseGrammarScanner/Resources/Grammar/contrasts/` 下的全部资料（简体中文原稿 `contrasts.json` 和 6 种语言的译文）。写新内容、改旧内容、复核内容都按这份标准。2026-11-21 经 Andy 确认。

## 三组都要做到的

1. **一组只有一个卖点，写在组说明（`note`）里。** 用户只看组说明，就该知道这一组要教他什么。
2. **组里每一条都要兑现这个卖点。** 放进某组，是因为它给出了这一组承诺的东西，不是因为「也有点关系」。三组都不合格的对比不收，原文移到 `docs/content/parked_contrasts.json`（待用清单），以后要用时再按单独的标准挑。不新增第四组。
3. **点进去的页面要讲的就是这个用法。** 对比对象的详情页里必须有被比的那个意思。反例：「〜ために」的意思组链接到「〜ような・〜ように・〜みたいな」，那一页讲的是比喻和举例，不是「为了」。
4. **例句是最小对比。** 两句尽量只换语法本身，用线索（时间词、后半句、原因）把差别逼出来；讲解（`explain`，界面上的「怎么分辨」）要说「看哪里就能分辨」。差别在接续上时，配一个确定错误的 ✗ 例（`wrong`）。
5. **虚线线索词必须是「怎么分辨」里点名的词。** 例句里用 `~` 标出的线索（界面上画虚线）必须是讲解里说的那个起决定作用的词。找不出这样的词就不标。反例：こんな／この 的例句把「いつか」画了虚线，讲解却没提它。
6. **例句里高亮的部分（`*` 开头的片段），App 自己的识别规则要能认出是这个语法点。** 否则用户拍下同样的句子，扫描结果和讲解对不上。
7. **同一个语法点详情页里，同一句例句不能出现第二次。** 范围是这一页用户看得到的全部例句：各义项的例句、场景例句、相近语法里两边的对比句。同一个用法要在两处讲，第二处重新造句。比较时忽略标点和空格。
8. **宁缺毋滥。** 一组挑不出合格的对比，就不写这一组。

## 同一个词变来的（`root`）

给用户的价值：知道一个源头词的本义，就能顺着推出、记住从它发展出的几个用法。

收录，必须全部满足：

- 两边确实来自同一个具体的词（动词、名词、助词或助动词），词源是真实的，不是民间说法。
- 从源头词的本义，能分别讲通两边的意思。讲不出这条路，就算同源也不收。

不收：

- 只是都含有一个到处都有的小成分（「て」「の」「に」），这个成分不承担两边的意思。
- 只是汉字或写法一样、意思推不过去的，归「长得像的」。

写法：

- 组说明写出源头词和它的本义：「都来自「X」——本义……」。
- 讲解说清从本义到这两个用法各自是怎么变过来的，而不只说两边各是什么意思。

好的例子：「〜とは限らない」和「〜に限らず」都来自「限る」（限定）：不限于这样 → 未必；不限于这个 → 不仅……也。

## 意思差不多的（`meaning`）

给用户的价值：同一个意思有哪几种说法，以及它们在语感和用法上细微的差别。差别必须是同一个意思里面的差别，不是两个不同的意思。

收录，必须全部满足：

1. 能用一个词说出共同意思，如「因为」「为了」「只」「虽然……但是」「一点也不」。「和时间有关」「能把两件事连起来」「和否定呼应」这类大类不算。
2. 这个意思是双方各自的正式用法（在各自详情页的义项里），不是翻译成中文碰巧一样。
3. 替换测试：至少有一个自然的句子，两个都能用，换了以后核心意思不变，只是语感变。找不到这样的句子，就不是意思差不多。
4. 差别讲的是同一个意思下的不同：主观或客观、口语、书面或郑重、带不带不满或强调、后面能不能接命令和请求、前面接什么。如果差别只能写成「A 表示甲；B 表示乙」，说明是两个意思，不收。

不收：

- 中文译法一样但意思不同的：〜ている 和 〜た（都可能译成「了」）。
- 同一类意思里程度不同的：全然〜ない（完全不）和 あまり〜ない（不太）。
- 意思相反的。

一个语法点有几个意思时（例如 〜ために 有「为了」和「因为」），每个意思各自一组「意思差不多的」，每组只对一个意思，不能混在一组里。资料格式和界面要先改好才能这样写；改好之前，只写这个语法点最主要的那个意思。

写法：

- 组说明写成「都表示「X」」，X 只有一个意思。
- 两句例句说的是同一个意思：同一句换掉语法后语感变了，或者一方在某个线索下（如句末的命令）不能用。
- 讲解写「什么时候选哪个」。

| | 组说明 | 对比 | 判断 |
| --- | --- | --- | --- |
| 好 | 都表示原因「因为……」 | ので ↔ から | 同一个意思；ので 客观委婉，から 主观，句末「〜からです」只能用 から |
| 差 | 都能表示「……着／……了」这类正在进行或状态持续、完成的意思 | ている ↔ た | 说明拼了几个意思；差别是「状态」对「发生了」，是两个意思 |
| 差 | 都表示「为了」或「因为」 | ために ↔ 〜ような・ように・みたいな | 两个意思混在一组；对方页面讲的是比喻 |
| 差 | 都表示「只、光」或「大约」 | ばかり ↔ くらい（大约） | ばかり 的另一个意思混进了主意思的组 |
| 差 | 都和「有名」搭配，说明在哪方面出名 | で有名 ↔ として | 共同点是搭配，不是意思 |

## 长得像的（`look`）

给用户的价值：点破平时一眼就会看错、考试里专门考的那种「长得几乎一样、意思完全不同」。

收录，必须全部满足：

1. 形状只差一个很小的地方：一个假名、促音或长音、浊点、一个助词；或者写法一样、读音不同；或者读音一样、写法不同（如 慣れる ↔ なれる）；或者尾巴一样、只有前面接的形式不同。
2. 意思明显不同。意思差不多的归「意思差不多的」。
3. 真会看错：读文章时容易读成另一个，或者是考试里常见的混淆项。

不收：

- 差了一整个词、一眼就能看出不同的。
- 只是共用一个常见成分、学习者不会弄混的。

写法：

- 组说明写出长得像的写法和差在哪里：「A ↔ B，只差……」；写法完全一样时，用「」写出这个写法。
- 讲解说清「看哪一处就能分辨」。

好的例子：ところ ↔ どころ，只差一个浊点；してから ↔ したから，只差 て／た，一个是「之后」，一个是「因为」；たら ↔ ったら，多一个促音。

## 自动检查

`python3 tools/validate_contrasts.py`（提交前和 CI 都会运行的资料校验脚本）检查下面几条，不通过就报错：

| 检查 | 对应上面 |
| --- | --- |
| 「意思差不多的」组说明里没有「」或「」「」／「」「，或」「有关」「这类」「之类」「搭配」「两种」 | 一组一个意思 |
| 「长得像的」组说明写出了写法（「↔」或「」） | 长得像的写法 |
| 「同一个词变来的」组说明用「」写出了源头词 | 同源写法 |
| 虚线线索词出现在这一条的「怎么分辨」里 | 第 5 条 |
| 例句高亮部分能被对应语法点的识别规则（`patterns`）认出 | 第 6 条 |
| 同一详情页内例句不重复 | 第 7 条 |

旧资料里还没改好的条目记在 `tools/contrast_debt.json`（待修清单）。清单外的内容必须通过；清单里的条目改好一条，运行 `python3 tools/validate_contrasts.py --update-debt` 把它移出清单。清单里有已经改好却没移出的条目也会报错，所以清单只会变短。

## 模型审核

下面这些机器规则判断不了，由模型逐条审核，不由人逐条看：词源是否真实、替换测试是否成立、差别讲的是不是同一个意思、对方页面是否真的讲这个意思、长得像的是否真会看错。

- 模型：opencode 上的 DeepSeek V4.1 Flash（`deepseek-v4.1-flash`），按这份标准的条目逐条判断，给出「通过」或「不通过」和理由。
- 先用已知答案的对比测准确度（如 ている ↔ た 应判不通过，ので ↔ から 应判通过），准确度够了再全量审。
- 全量审要花钱，运行前先报费用，Andy 同意后再跑。
