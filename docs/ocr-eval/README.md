# 扫描识别评测（基准数据）

这里记录「拍照 → 文字识别 → 语法点识别 → 高亮框」整条链路的评测方法、数据集和每一版的结果。
以后任何涉及扫描、框选、语法识别的优化，都必须在同一套数据和指标上重新评测，并把结果追加到这里，
和历史版本对比后再决定是否上线。

## 目录

| 路径 | 内容 |
|---|---|
| `tests/ocr/samples/` | 评测用的真实照片（95 张，用户实拍的教材、模拟题、单词书等） |
| `tests/ocr/groundtruth/` | 每张照片的标准正文（人工逐字转写：只含印刷的日文，不含注音、手写、非日文） |
| `tests/ocr/groundtruth/labels.json` | 每张照片的类别与难点标签（带注音、多语言、斜拍、弯曲、手写批注、深色底……） |
| `docs/ocr-eval/runs/<日期>_<版本>.md` | 每一版的评测报告：现状、采用的技术、结果、结论 |
| `docs/ocr-eval/runs/<日期>_<版本>.json` | 同一版的完整指标（总体 + 每张图），供以后程序化对比 |
| `docs/ocr-eval/HISTORY.md` | 各版本核心指标一览表（每次评测后追加一行） |
| `tools/ocr_eval.py` | 离线评测脚本（读取 CI 导出的识别结果，与标准正文对比，输出指标与报告） |
| `.github/workflows/ocr-eval.yml` | 在 CI 的 iOS 模拟器上对全部照片跑 Apple Vision 文字识别，导出原始结果 |

## 怎么重新评测

1. 在 GitHub Actions 手动运行「OCR Eval」（或修改识别相关代码后自动触发），下载产物 `ocr-out`。
2. `python3 tools/ocr_eval.py <ocr-out 目录> --report docs/ocr-eval/runs/<日期>_<版本>`
3. 把报告里的结论补充完整，在 `HISTORY.md` 追加一行。

## 指标定义

### 1. 文字识别（扫描）
| 指标 | 定义 | 越… 越好 |
|---|---|---|
| 字符准确率 | 1 − 字符错误率（CER）。CER =（替换 + 删除 + 插入）/ 标准正文字数，按编辑距离计算，忽略空白 | 高 |
| 字召回 / 字精确 | 与顺序无关的字符重合度：标准正文的字有多少被识别出来 / 识别结果的字有多少是正文里的。多栏页面阅读顺序不同时，用来区分「认错字」和「顺序不同」 | 高 |
| 假名插入率 | 识别结果相对标准正文多出（或替换进来）的假名字符占比，主要来自注音干扰 | 低 |
| 噪声插入率 | 识别结果相对标准正文多出的非日文字符（英文、越南文、韩文、乱码）占比 | 低 |
| 平均耗时 | 每张照片识别所需时间（模拟器上测得，只用于版本间相对比较） | 低 |

### 2. 语法点识别
标准答案 = 用当前语法规则在「标准正文」上找到的语法点集合（理想 OCR 下 App 应该给出的结果）。
| 指标 | 定义 | 越… 越好 |
|---|---|---|
| 召回率 | 标准答案中的语法点，有多少在实际识别结果中也被找到（衡量漏识别） | 高 |
| 精确率 | 实际识别出的语法点，有多少确实在标准答案中（衡量 OCR 噪声造成的误报） | 高 |
| F1 | 召回率与精确率的调和平均，作为综合指标 | 高 |
| 整页全对率 | 识别结果与标准答案完全一致的照片比例 | 高 |

> 局限：这一组指标衡量的是「OCR 链路造成的损失」。语法规则本身的误判（例如把词语中间的「に」当成语法）
> 在标准正文上也会发生，不会体现在这里；规则本身的准确率需要人工逐条标注语法点后另行评测（见路线图）。

### 3. 高亮框
| 指标 | 定义 | 越… 越好 |
|---|---|---|
| 精确定位率 | 高亮框中由 Vision 直接给出逐字位置（而不是按字数比例估算）的比例 | 高 |
| 框选正确率 | 抽样把高亮框画在照片上，逐个检查框是否正好框住对应的语法文字（人工/视觉复核） | 高 |

### 按难点分组
每项指标同时按照片标签分组统计（带注音 / 多语言对照 / 斜拍或弯曲 / 手写批注 / 深色底 / 长篇正文 / 对话气泡），
用来判断某项改进对哪类页面有效、对哪类页面有副作用。

## 规则准确率（build 11 起）

上面的语法指标用「同一套规则在标准正文上的命中」作为标准答案，**测不出规则本身过宽**造成的误报。
所以另外抽检：从标准正文的全部命中中，每个语法点随机抽 ≤5 处，逐条判断是否真的是该语法点（判断标准 `rule-audit/AUDIT_PROMPT.md`），
按命中次数加权得到「规则准确率」。抽样与判断结果存放在 `rule-audit/`。修改语法规则后，对改动的规则重新抽样，在报告里写明前后数字。
